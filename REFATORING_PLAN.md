# Подробный план рефакторинга файла app/main.py

## Цель
Разбить огромный файл `app/main.py` (более 12000 строк) на логически связанные модули, чтобы упростить поддержку, тестирование и читаемость кода.

## Проблемы с текущим файлом
- 12000+ строк кода в одном файле
- Нарушение принципа единственной ответственности
- Сложно тестировать и отлаживать
- Всё сплошняком - сложно ориентироваться

## План разбиения

### 1. API маршруты
Разделить текущие API маршруты по категориям:

#### Новый путь: `api/tracks.py`
- /api/v1/tracks/*
- /tracks/* (если не попадают в другую категорию)
- Связанные функции

#### Новый путь: `api/releases.py`
- /api/v1/releases/*
- /releases/* 
- Связанные функции

#### Новый путь: `api/artists.py`
- /api/v1/artists/*
- Связанные функции

#### Новый путь: `api/mixes.py`
- /api/v1/mixes/*
- /mixes/*
- Функции и методы, связанные с генерацией миксов

#### Новый путь: `api/search.py`
- /api/v1/search/*
- /search/*
- Все функции, связанные с поиском

#### Новый путь: `api/playback.py`
- /api/v1/playback/*
- Функции и методы, связанные с воспроизведением

#### Новый путь: `api/analyzer.py`
- Маршруты, связанные с обучением и анализом (analyze, index, etc)
- Соответствующие функции

#### Новый путь: `api/settings.py`
- /api/v1/settings/*
- Связанные функции настроек

### 2. Модели данных
#### Новый путь: `schemas/responses.py`
- Все классы, которые относятся к ответам API (ApiErrorResponse, ArtistResponse и т.д.)

#### Новый путь: `schemas/requests.py`
- Все классы, которые относятся к запросам API (AnalyzeRequest, PlaybackSessionCreateRequest и др.)

### 3. Утилитарные функции
#### Новый путь: `utils/transforms.py`
- Функции преобразования данных: track_summary_dict, playback_session_dict и др.

#### Новый путь: `utils/logging.py`
- Настройки и функции логирования

#### Новый путь: `utils/cache.py`
- Управление кэшем (COVER_CACHE, STATS_CACHE и др.)

#### Новый путь: `utils/helpers.py`
- Вспомогательные функции типа _bounded_int, _json_object и др.

### 4. Бизнес-логика
#### Новый путь: `services/recommender_service.py`
- Логика рекомендаций

#### Новый путь: `services/analysis_job_service.py`
- Управление задачами анализа (jobs)

#### Новый путь: `services/index_service.py`
- Бизнес-логика по индексации данных

#### Новый путь: `services/playback_service.py`
- Все, что связано с логикой воспроизведения

#### Новый путь: `services/mixes_service.py`
- Логика по генерации плейлистов

#### Новый путь: `services/search_service.py`
- Бизнес-логика поиска

### 5. Конфигурация
#### Новый путь: `config/settings.py`
- Переменные конфигурации (COVER_TIMEOUT_SECONDS и т.п.)

#### Новый путь: `config/globals.py`
- Глобальные переменные: JOBS, COVER_CACHE, STATISTICS и др.

### 6. Миддлевар и обработка исключений
#### Новый путь: `middleware/log_middleware.py`
- log_http_request

#### Новый путь: `middleware/exception_handler.py`
- api_v1_validation_exception_handler

## Пошаговая стратегия

1. Создать новую директорию `api/` и начать с простых маршрутов (типа `/health`)
2. Мигрировать модели в `schemas/`
3. Выносить утилиты в `utils/`
4. Двигаться к более сложным бизнес-сервисам
5. Адаптировать импорты в `main.py`, постепенно сокращая сам файл
6. Тестировать на каждом этапе, чтобы не сломать приложение

## Рекомендации по безопасности
- Запускать тесты регулярно на каждом этапе рефакторинга
- Подтверждать функциональность интеграционными тестами
- Следить за циклическими зависимостями между модулями
- Обновлять типовые сценарии использования при необходимости

Следование этому плану должно существенно упростить архитектуру приложения и улучшить опыт разработки.
