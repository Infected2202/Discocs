## 1. ISRC / UPC — главное (авто-тегирование вместо ручного Picard)

**Проблема.** Ручной матч библиотеки в Picard на таком объёме — дни работы. Picard ищет
релиз по отпечатку звука (AcoustID) и по названиям; по ISRC/штрихкоду сам не ищет,
даже если они уже есть в тегах.

**Что есть (проверено):**

- Deezer отдаёт `isrc` у трека (`api.deezer.com/track/{id}`) и `upc` у альбома
  (`api.deezer.com/album/{id}`), ключ не нужен.
- deemix пишет их в теги (в `%APPDATA%\deemix\config.json` включены `tags.isrc`,
  `tags.barcode`): FLAC — `ISRC`, `BARCODE`; MP3 — `TSRC`, `TXXX:BARCODE`.
  В Mp3tag по умолчанию не видны — только в расширенном редакторе или колонкой
  `%isrc%` / `%barcode%`.
- Снимок Navidrome (Subsonic API, OpenSubsonic-поля) на 58 000 треков: `isrc` у ~35 800,
  `musicBrainzId` у ~33 900.

**Идея.** Скрипт: ISRC/штрихкод из тегов → MusicBrainz (поиск записи по ISRC, релиза по
barcode) → MBID в теги → Picard/Navidrome сразу видят нужный релиз. Ручная работа —
только для старых файлов без кодов. Как именно сопоставлять (неоднозначности: один ISRC
на нескольких релизах, переиздания) — решать по месту.

## 2. Популярность: `rank` и `fans` (Deezer)

Проверено:

- `rank` трека — число популярности (Daft Punk: «Get Lucky» 954 234, «Instant Crush» 942 491).
  Порядок `artist/{id}/top` не строго по `rank`.
- `fans` альбома — сколько людей добавили себе (Discovery — 342 409). Отдельный запрос
  на альбом; в дискографии через deemix (`/api/getTracklist`) `fans` приходит пустым.
- `nb_fan` у артиста.

Применение: сигнал в рекомендации, показ «популярного у артиста». Прослушиваний и
чартов по стримам публичный API не даёт.

## 3. Last.fm (ключ уже есть в music-fill)

Не проверено:

- `artist.getSimilar` / `track.getSimilar` со степенью похожести — «как слушают люди»,
  дополнение к «как звучит» от эмбеддингов.
- Теги артистов/треков (жанры, настроения) — точнее жанров Deezer.
- Глобальные listeners/playcount.
- Личная история скробблов с 2008 уже выгружена music-fill (`raw/lastfm/`, ~115 тыс.).

## 4. Связи между артистами и подборки (Deezer)

Потенциально полезно, как применить — думать:

- `artist/{id}/related` — похожие артисты (music-fill уже использует в поиске), граф артистов.
- `artist/{id}/radio` — поток треков «в духе артиста».
- `chart/{genre}/tracks|albums|artists`, `editorial/0/releases` — чарты и новые релизы
  (под задачу «следить за новыми релизами»).

## 5. 30-секундные превью для эмбеддингов — под вопросом

У каждого трека Deezer есть ссылка на mp3-превью 30 с. Теоретически — эмбеддинги
для треков, которых нет в библиотеке (кандидаты для рекомендаций/поиска новой музыки).
Минусы: 30 с дают плохой эмбеддинг (может попасть интро или пробитовка), всю базу
Deezer не соскрепить. Есть над чем подумать, например как дешёвый предфильтр кандидатов.
