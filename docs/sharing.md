# Публичный шаринг

Discocs может создавать отзывные публичные ссылки на один трек или релиз.
Получателю не нужна учётная запись: `/share/{token}` открывает отдельный
адаптивный плеер, а релиз отображается как упорядоченная очередь с обложками.
Цветовой акцент плеера извлекается из обложки. Логотип Discocs в шапке ведёт на главную.

## Модель безопасности

Публичная ссылка — capability URL: знание полного токена даёт доступ только к
snapshot-набору треков этой ссылки. Токен генерируется из 256 бит случайности;
в SQLite хранится только его SHA-256 и короткий префикс для management UI.

Ссылка перестаёт работать сразу после отзыва или окончания срока. Неизвестные,
истёкшие и отозванные токены снаружи возвращают одинаковый `404`.

Полный токен показывается владельцу только при создании. Его нельзя восстановить
из БД или списка ссылок: вместо этого создаётся новая ссылка.

Получатель может сохранить аудио и переслать capability URL другому человеку —
это свойство ссылки, а не следствие наличия кнопки скачивания. Тот, кто способен
воспроизвести поток в браузере, всё равно может сохранить байты; см.
[Скачивание](#скачивание).

## Конфигурация

Sharing включён по умолчанию. Для явного отключения:

```text
DISCOCS_SHARING_ENABLED=false
DISCOCS_SHARE_DEFAULT_TTL_HOURS=168
DISCOCS_SHARE_MAX_TTL_HOURS=8760
DISCOCS_SHARE_MAX_STREAMS_PER_CLIENT=3
DISCOCS_SHARE_MAX_STREAMS=16
DISCOCS_PUBLIC_URL=https://music.example.com
```

- При включённом sharing ссылки может создавать любой обычный
  авторизованный пользователь. Анонимный и service principal не могут
  управлять ссылками.
- `DISCOCS_PUBLIC_URL` задаёт canonical origin генерируемого URL. Если он пуст,
  backend использует browser-visible request origin через frontend proxy.
- Лимиты потоков действуют в памяти одного backend process. При горизонтальном
  масштабировании нужен общий distributed limiter.

Production `.env` хранится на сервере и не обновляется Jenkins.
Если `DISCOCS_SHARING_ENABLED` в нём не задан, compose передаёт backend значение `true`.

## API

Авторизованное управление:

```text
GET    /api/v1/shares/capabilities
POST   /api/v1/shares
GET    /api/v1/shares
GET    /api/v1/shares/{id}
PATCH  /api/v1/shares/{id}
DELETE /api/v1/shares/{id}
```

`DELETE` выполняет идемпотентный revoke. Владелец видит только свои записи;
чужой идентификатор возвращает `404`.

Публичны только точные `GET|HEAD` маршруты:

```text
GET  /api/v1/public/shares/{token}
GET  /api/v1/public/shares/{token}/preview
HEAD /api/v1/public/shares/{token}/preview
GET  /api/v1/public/shares/{token}/cover
HEAD /api/v1/public/shares/{token}/cover
GET  /api/v1/public/shares/{token}/items/{position}/audio
HEAD /api/v1/public/shares/{token}/items/{position}/audio
```

Audio endpoint принимает позицию snapshot-элемента, не внутренний track ID.
Backend проверяет `(token_hash, position)` до чтения файла или обращения в
Navidrome. Локальный путь, owner ID и Navidrome ID в публичный JSON не попадают.

Metadata интерактивного плеера требует revalidation (`private, no-cache`), а
обычная обложка и аудио кешируются только в браузере получателя на один час
(`private, max-age=3600`). Ошибки не кешируются. Эти ответы также используют
`no-referrer`, `nosniff` и `noindex,nofollow,noarchive`; CORS для share не
включается. Revoke немедленно закрывает новые запросы к origin, но не может
отозвать уже полученные или сохранённые браузером байты.

## Аудио

Локальные файлы читаются только по пути индексированного разрешённого Track.
Navidrome-треки проксируются серверным service account: credentials владельца
не сохраняются в share и не выдаются гостю. Поддерживаются HEAD, Range и seek.

Публичный Navidrome-поток всегда транскодируется в MP3 320 кбит/с независимо от
личных настроек создателя. Локальный fallback-файл отдаётся в исходном формате,
поскольку встроенного локального транскодера у backend нет.

### Длина потока

Транскодированный ответ обязан нести `Content-Length`. Navidrome отдаёт его по
`estimateContentLength=true`, считая из bitrate × duration; для CBR-профилей,
которые мы запрашиваем, это точное значение. Раньше заголовок срезался, чтобы
поток, не добравший до объявленной длины, не ронял ответ на уровне ASGI
(«Response content shorter than Content-Length»). Побочный эффект оказался
дороже проблемы: запрос **без** `Range` не получал ни `Content-Length`, ни
`Content-Range`, то есть вообще никакой информации о длине. Медиаэлемент в
таком случае показывает `duration === Infinity`, не умеет построить
байтовый диапазон и отказывается перематывать — ползунок на share-странице
превращался в мёртвую полосу с `0:00 / 0:00`. Клиентов, которые сами шлют
`Range`, спасал только `Content-Range` с общим размером в хвосте.

Теперь длина сохраняется, а генератор тела приводит поток к ней: недобор
добивается нулями, перебор обрезается. Ответ остаётся корректным при любом
поведении upstream, и 200, 206 и HEAD одинаково сообщают размер. Если Navidrome
прислал неразбираемый `Content-Length`, заголовок отбрасывается — на проводе он
хуже, чем его отсутствие.

Основной плеер обходил ту же проблему на клиенте (`PlayerPlaybackFacade`:
длительность из API-метаданных плюс подмена источника на полностью скачанный
Blob). Для публичной ссылки этот путь неприемлем — он означает выкачивание
всего трека на чужом мобильном трафике ради одной перемотки, — поэтому share
опирается на корректные заголовки, а не на локальную копию.

## Скачивание

Публичный плеер даёт скачать аудио — потрековым меню у текущего трека и у
каждой строки очереди, и меню всего списка в заголовке очереди:

- `GET /api/v1/public/shares/{token}/items/{position}/download` — один трек;
- `GET /api/v1/public/shares/{token}/download` — весь share одним ZIP.

Оба URL публикуются в метаданных (`download_url` у элемента и у самого share),
чтобы фронтенд не собирал их из кусков.

Гостю уходит **тот же MP3 320, что и в плеере**, а не оригинал. Транскод берётся
через `stream`-эндпоинт Navidrome: `download` всегда отдаёт исходный файл и молча
игнорирует параметры формата. Расширение имени файла определяется по
`Content-Type` ответа, а не по индексированному пути, — иначе перекодированный
FLAC сохранялся бы как `.flac` и не открывался бы ни одним плеером. Локальный
fallback-файл (трек без маппинга в Navidrome) уходит в исходном формате: своего
транскодера у backend нет, ровно как и при стриминге.

Скачивание доступно на любой действующей ссылке и отдельным флагом не
управляется. Отзыв и срок действия работают как для всего остального: оба
эндпоинта проходят ту же проверку живости ссылки и отвечают неотличимым 404 при
любой причине отказа. Ответы помечены `private, no-store`. Слот-лимит
одновременных стримов на скачивание не распространяется.

ZIP собирается потоково (`stream_track_archive`), без буферизации трека или
архива целиком; трек, который не удалось прочитать, не роняет архив, а попадает
в `DOWNLOAD_ERRORS.txt` внутри него.

## Диалог создания ссылки

Поле названия **не получает фокус при открытии**. На телефоне автофокус
немедленно поднимает экранную клавиатуру, которая закрывает половину диалога, —
и всё ради поля, которое по умолчанию и так подставляет название источника
(оно показано плейсхолдером, а пустое значение backend заменяет сам). Radix
фокусирует первый элемент по умолчанию, поэтому `onOpenAutoFocus` отменяется,
а фокус переводится на сам контейнер диалога: ловушка фокуса, Escape и порядок
табуляции продолжают работать, но каретки нигде нет.

Пока диалог открыт, `useVisualViewportFit` следит за `visualViewport`.
Экранная клавиатура ужимает visual viewport, не трогая layout viewport, поэтому
отцентрованный `fixed`-элемент оказывается за клавиатурой. Хук считает,
насколько поднять диалог и какой у него допустимый максимум высоты. На десктопе
и в браузерах без этого API оба значения нейтральны, и ничего не двигается.

Созданная ссылка **копируется в буфер автоматически**, без нажатия на кнопку
копирования: секрет показывается ровно один раз, и случайный тап мимо диалога
не должен его стоить. Запись в буфер может быть отклонена сама по себе
(незащищённое origin, отказ в разрешении, устаревшая user activation после
ожидания запроса) — в этом случае ошибка не показывается и не выдаётся за сбой
создания ссылки: кнопка копирования остаётся на месте, и подтверждение
«Скопировано» не появляется.

## Карточки ссылок

Для preview-клиентов nginx направляет `/share/{token}` в серверный HTML endpoint.
Он отдаёт стандартные Open Graph и Twitter Card метатеги: название трека или
релиза, исполнителя, альбом/год, длительность, число треков и абсолютный URL
обложки. Рекламного текста и `og:audio` в карточке нет. Формат не привязан к
Telegram и подходит также для Steam Chat, Discord, Slack и других клиентов,
которые поддерживают обычный link unfurl. Обычный браузер по тому же URL получает
интерактивный SPA-плеер.

`og:type` намеренно равен универсальному `website`: специальные типы
`music.song`/`music.album` не используются без `og:audio`, чтобы Telegram не
переводил безопасную карточку метаданных в незавершённый media-preview.

HTML unfurl и его обложка не содержат аудио или внутренних идентификаторов и
отдаются без robots-запрета с коротким публичным кешем (5 минут для HTML, один
час для картинки). Это необходимо, чтобы Telegram и другие внешние preview-
сервисы могли сохранить карточку. Интерактивная страница, JSON и аудио остаются
`private`/`noindex`. После отправки ссылки копия метаданных и обложки уже может
жить в кеше мессенджера независимо от последующего revoke.

Для принудительного обновления карточки поддерживается безопасный параметр
`?v=<метка>` (только латинские буквы, цифры, `_` и `-`, до 64 символов). Он
включается в `canonical` и `og:url`, поэтому preview-сервисы воспринимают URL как
новую версию, но на содержимое и права capability-ссылки параметр не влияет.

## Reverse proxy

Публичный frontend nginx:

- продолжает очищать входящий `X-Discocs-Service-Token`;
- проксирует только общий `/api` контур;
- не открывает admin/workers/settings/jobs;
- маскирует секретные части `/share/{token}` и public API в access log;
- отдаёт share page с `Referrer-Policy: no-referrer` и запретом индексации.
- распознаёт link-preview crawler по User-Agent и отдаёт ему только безопасные
  серверные метаданные без аудиопотока.

Публичный seek использует тот же drag-механизм, что основной плеер: во время
перетаскивания интерфейс показывает выбранную позицию, а запрос на перемотку
выполняется один раз при отпускании указателя.

Длительность берётся из `duration` медиаэлемента только если она конечна и
положительна, иначе — из метаданных share API (`resolveDuration`). Проверка
именно на конечность, а не на truthiness: `Infinity` истинен, и наивное
`element.duration || api.duration` подставляло бы его вместо честного значения.

Бегунок ползунка виден без hover (`.share-seek-thumb`, тот же приём, что у
`.track-menu-trigger`): на тач-экране hover-состояния нет, и спрятанная за ним
точка не рисовалась никогда.

Не публикуйте backend-порт `8711` напрямую в интернет. Внешний TLS proxy должен
передавать исходный Host и HTTPS scheme, не логируя capability URL целиком.

## Эксплуатация

В Settings → Shared links видны источник, срок, статус, число открытий и revoke.
IP получателей не сохраняются. `access_count` — диагностический счётчик открытия
metadata, а не персональная playback-аналитика и не сигнал рекомендаций.

Если ссылка не работает, проверить по порядку:

1. включён ли feature flag;
2. не истёк и не отозван ли share;
3. остались ли snapshot-треки в каталоге и не помечены ли они missing;
4. доступны ли local mount или service credentials Navidrome;
5. не достигнут ли stream limit (`429`, `Retry-After: 60`).
