# Telegram: привязка аккаунта и «Отправить в Telegram»

Пользователь discocs может привязать свой Telegram-аккаунт к боту
(`discocs_bot/`) и отправлять треки и релизы из диалога «Поделиться» в личный
чат с ботом. Это отдельно от публичной ссылки: ссылка не создаётся, а
получатель — всегда сам пользователь.

Бот при этом остаётся открытым: привязка не гейт доступа, а только связь
«Telegram-аккаунт ↔ пользователь discocs» для интеграций.

## Привязка (deep link)

1. В «Настройки → Telegram» пользователь жмёт «Подключить Telegram».
   `POST /api/v1/telegram/link` создаёт одноразовый токен (10 минут,
   `DISCOCS_TELEGRAM_LINK_TTL_MINUTES`) и возвращает
   `https://t.me/<bot>?start=link_<token>`. Имя бота backend узнаёт у самого
   бота (`GET /internal/info`) и кэширует.
2. Пользователь открывает ссылку и жмёт Start. Бот получает
   `/start link_<token>` и отправляет `POST /api/v1/telegram/link/redeem`
   с токеном и `telegram_user_id`, который ему сообщил Telegram.
3. Backend гасит токен и записывает связь в `telegram_links`.

Пароль через Telegram не передаётся: кто это, уже доказала веб-сессия, в
которой создан токен. Токен одноразовый и короткоживущий, в БД лежит только его
SHA-256 (`telegram_link_tokens`). Новый токен того же пользователя отменяет
предыдущий.

Один Telegram-аккаунт привязан максимум к одному пользователю и наоборот:
повторная привязка переносит/заменяет связь. Отвязать — кнопка «Отвязать» в
настройках (`DELETE /api/v1/telegram/link`).

## Отправка

Кнопка «Отправить в Telegram» видна в диалоге «Поделиться», если аккаунт
привязан. `POST /api/v1/telegram/send` `{source_type, source_id}`:

- **трек** — backend находит Navidrome song id и просит бота отправить его;
  бот сразу шлёт карточку загрузки с обложкой (это же проверяет, что он может
  писать в чат), отвечает `202`, а аудио готовит в фоне тем же путём, что и
  кнопка «Получить» в боте (транскод, кэш `file_id`, профиль качества
  пользователя в боте);
- **релиз** — карточка альбома: обложка, артист — название, год, число треков,
  кнопки «📀 Отправить все треки» (существующая доставка альбома) и
  «🌐 Открыть в discocs» (`<DISCOCS_PUBLIC_URL>/releases/<id>`). Если Telegram
  отвергает URL (localhost, голый IP без `DISCOCS_PUBLIC_URL`), карточка уходит
  без «Открыть».

Отправляются только Navidrome-элементы: локальный трек без Navidrome id → `422
not_in_navidrome`.

Коды ошибок `/send`: `409 telegram_not_linked`, `409 telegram_chat_unavailable`
(пользователь не запускал бота или заблокировал его), `503
telegram_bot_unavailable` (бот не настроен/не отвечает), `502
telegram_send_failed`, `404`/`422` по источнику.

## Сеть и безопасность

Telegram API доступен только через awg-туннель, поэтому backend в Bot API не
ходит. Бот поднимает внутренний HTTP (`bot/services/internal_api.py`, aiohttp)
на `BOT_INTERNAL_PORT` (8090). Бот сидит в сетевом неймспейсе `awg`, поэтому
backend стучится в `http://awg:8090` (`DISCOCS_BOT_URL`).

- Каждый запрос в обе стороны несёт `X-Discocs-Service-Token`
  (`DISCOCS_SERVICE_TOKEN`, один на backend/бот). Без токена бот внутренний
  сервер не поднимает.
- `/api/v1/telegram/link/redeem` принимает только service principal, а
  пользовательские эндпоинты — только сессию. Значит, пользователь не может
  привязать к себе чужой Telegram id, а бот — пользоваться чужой сессией.
- В `start-awg.sh` порт 8090 закрыт со стороны интерфейса туннеля.

Функция требует включённого гейта (`DISCOCS_AUTH_ENABLED=true`): без сессии нет
пользователя, без service principal нет `redeem`.

## Конфигурация

| Переменная | Где | По умолчанию | Смысл |
|---|---|---|---|
| `DISCOCS_BOT_URL` | backend | `http://awg:8090` в prod compose, иначе пусто | адрес бота; пусто — функция выключена |
| `DISCOCS_TELEGRAM_LINK_TTL_MINUTES` | backend | `10` | срок жизни токена привязки |
| `BOT_INTERNAL_PORT` | бот | `8090` | порт внутреннего HTTP (менять вместе с `start-awg.sh`) |
| `BOT_INTERNAL_HOST` | бот | `0.0.0.0` | адрес прослушивания |
| `DISCOCS_SERVICE_TOKEN` | оба | — | общий секрет; обязателен |
