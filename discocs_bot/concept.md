# Discocs Bot MVP — концепт приложения

## 1. Краткое описание

**Discocs Bot** — закрытый Telegram-бот для доступа к личной музыкальной библиотеке Navidrome через Telegram.

Основная задача MVP: дать пользователю быстрый способ найти трек в библиотеке, получить его как аудиофайл в Telegram и построить “радио по треку” на основе рекомендаций Discocs.

Бот не является полноценной заменой Navidrome Web UI. Он решает более узкую задачу: сделать музыкальную библиотеку удобной для использования внутри Telegram, особенно в личных и групповых чатах.

## 2. Цель MVP

Создать минимально рабочий Telegram-бот, который позволяет:

1. Искать треки в Navidrome.
2. Отправлять найденные треки в Telegram как аудиофайлы.
3. Автоматически транскодировать FLAC в MP3 перед отправкой.
4. Кэшировать уже отправленные Telegram-файлы через `file_id`.
5. Получать похожие треки через Discocs.
6. Быстро отправлять рекомендованные треки в чат.
7. Ограничивать доступ к боту списком разрешенных Telegram-пользователей.

## 3. Проблема

Navidrome удобен как музыкальный сервер, но его веб-интерфейс не является основной средой общения для пользователей. Большинство друзей уже слушают и пересылают музыку в Telegram.

Из-за этого возникает разрыв:

* музыка хранится в Navidrome;
* рекомендации строятся в Discocs;
* общение и обмен музыкой происходят в Telegram.

Discocs Bot должен стать простой точкой входа в библиотеку из Telegram.

## 4. Пользовательская ценность

Бот позволяет:

* быстро найти трек в своей библиотеке;
* отправить его в Telegram без ручного скачивания;
* делиться музыкой с друзьями в привычной среде;
* получать похожие треки через радио;
* использовать Telegram как удобный интерфейс к личной музыкальной коллекции.

Ключевая формула продукта:

> Личная музыкальная библиотека, которую можно вызвать прямо из Telegram.

## 5. Основные пользователи

### Владелец библиотеки

Администратор Navidrome/Discocs, который хочет удобно доставать музыку из своей коллекции и делиться ей в Telegram.

Права:

* полный доступ к поиску;
* отправка любых треков;
* радио по треку;
* доступ к debug-командам;
* возможность добавлять пользователей в allowlist в будущем.

### Друзья

Пользователи, которым владелец открыл доступ к боту.

Права MVP:

* поиск треков;
* получение аудиофайлов;
* радио по треку;
* отправка найденных треков в чат.

### Неавторизованные пользователи

Пользователи, не входящие в allowlist.

Поведение:

* бот не раскрывает библиотеку;
* отвечает коротким сообщением об отсутствии доступа.

## 6. MVP-сценарии

### Сценарий 1: поиск трека

Пользователь пишет:

```text
/search burial archangel
```

Бот ищет треки в Navidrome и возвращает список результатов.

Пример ответа:

```text
Нашел треки:

1. Burial — Archangel
   Untrue · 2007

2. Burial — Near Dark
   Untrue · 2007

3. Burial — Etched Headplate
   Untrue · 2007
```

Под каждым треком отображаются кнопки:

```text
[🎧 Отправить] [📻 Радио]
```

### Сценарий 2: отправка трека

Пользователь нажимает:

```text
🎧 Отправить
```

Бот проверяет, есть ли у трека сохраненный Telegram `file_id`.

Если `file_id` есть:

* бот мгновенно отправляет аудио через Telegram file cache.

Если `file_id` нет:

* бот получает трек из Navidrome;
* транскодирует его в MP3;
* отправляет аудиофайл в Telegram;
* сохраняет полученный `file_id` в локальную SQLite-базу.

### Сценарий 3: радио по треку

Пользователь нажимает:

```text
📻 Радио
```

Бот вызывает Discocs и получает список похожих треков.

Пример ответа:

```text
Радио от Burial — Archangel:

1. ...
2. ...
3. ...
4. ...
5. ...
```

Под каждым рекомендованным треком снова доступны кнопки:

```text
[🎧 Отправить] [📻 Радио]
```

Это позволяет бесконечно перемещаться по библиотеке через цепочку похожих треков.

### Сценарий 4: случайный трек

Пользователь пишет:

```text
/random
```

Бот возвращает случайный трек из библиотеки.

Кнопки:

```text
[🎧 Отправить] [📻 Радио]
```

### Сценарий 5: старт и справка

Пользователь пишет:

```text
/start
```

Бот отвечает краткой справкой:

```text
Discocs Bot — доступ к музыкальной библиотеке.

Команды:
/search query — найти трек
/random — случайный трек
/help — справка

Под треками доступны кнопки:
🎧 Отправить — прислать аудиофайл
📻 Радио — найти похожие треки
```

## 7. Что входит в MVP

### Telegram bot

* Команды `/start`, `/help`, `/search`, `/random`.
* Inline-кнопки под треками.
* Обработка callback-запросов.
* Проверка доступа по Telegram user ID.
* Отправка аудиофайлов в чат.

### Navidrome integration

* Поиск треков.
* Получение метаданных трека.
* Получение аудиопотока или файла.
* Получение случайного трека, если возможно через API или внутреннюю выборку.

### Discocs integration

* Получение похожих треков по Navidrome song ID.
* Поддержка параметров:

  * count;
  * model;
  * max_per_artist;
  * exclude_same_album.

### Transcoding

* Транскод FLAC или другого исходного формата в MP3.
* Битрейт по умолчанию: 192 kbps.
* Использование `ffmpeg`.
* Сохранение временного или кэшированного MP3-файла.
* Проверка лимита размера перед отправкой.

### File cache

* Хранение Telegram `file_id`.
* Повторная отправка трека без повторного транскода.
* SQLite как локальное хранилище MVP.

## 8. Что не входит в MVP

В первой версии не реализуются:

* Telegram Inline Mode через `@bot query`;
* Telegram Mini App;
* подборки по вайбу;
* mood/genre filters;
* персональные рекомендации;
* загрузка пользовательских аудиофайлов для поиска похожего;
* полноценный web UI;
* плейлисты;
* управление альбомами;
* сложная система ролей;
* публичная регистрация пользователей;
* статистика прослушиваний;
* scrobble в Navidrome.

Эти функции могут быть добавлены после проверки базового сценария: поиск → отправка → радио.

## 9. UX-принципы

### 9.1 Минимум команд

Пользователь не должен запоминать много команд. MVP использует небольшой набор:

```text
/start
/help
/search
/random
```

Основное взаимодействие происходит через кнопки.

### 9.2 Трек как основная единица интерфейса

Каждый трек отображается как карточка:

```text
Artist — Title
Album · Year
```

Кнопки:

```text
[🎧 Отправить] [📻 Радио]
```

### 9.3 Радио как основной способ навигации

Так как в MVP нет вайбов и подборок, радио по треку становится главным способом исследования библиотеки.

Пользователь может начать с любого трека и дальше перемещаться по похожим.

### 9.4 Telegram как delivery-интерфейс

Бот не должен пытаться заменить музыкальный плеер. Его задача — быстро доставить трек в Telegram в виде аудиофайла, который можно слушать, переслать или использовать в чате.

## 11. Основные сервисы

### 11.1 NavidromeClient

Отвечает за работу с Navidrome/Subsonic API.

Методы MVP:

```text
ping()
search_tracks(query, limit)
get_song(song_id)
get_stream(song_id)
get_random_tracks(limit)
```

### 11.2 DiscocsClient

Отвечает за рекомендации.

Методы MVP:

```text
get_similar(song_id, count, model, max_per_artist, exclude_same_album)
```

Возвращает список похожих Navidrome song IDs и score.

### 11.3 Transcoder

Отвечает за подготовку файла к отправке в Telegram.

Методы MVP:

```text
transcode_to_mp3(input_path, output_path, bitrate)
get_audio_duration(path)
get_file_size(path)
```

### 11.4 DeliveryService

Главный сервис доставки треков.

Метод MVP:

```text
send_track(chat_id, song_id)
```

Логика:

```text
1. Получить метаданные трека.
2. Проверить наличие telegram_file_id в SQLite.
3. Если file_id есть — отправить cached audio.
4. Если file_id нет:
   4.1 получить файл из Navidrome;
   4.2 транскодировать в MP3;
   4.3 отправить аудио в Telegram;
   4.4 сохранить telegram_file_id;
   4.5 очистить временные файлы при необходимости.
```

### 11.5 Storage

SQLite-хранилище для:

* кэша Telegram file_id;
* пользователей;
* событий;
* временных callback references, если потребуется.

## 12. SQLite-схема MVP

### Таблица audio cache

```sql
CREATE TABLE telegram_audio_cache (
    navidrome_song_id TEXT PRIMARY KEY,
    telegram_file_id TEXT NOT NULL,
    telegram_file_unique_id TEXT,
    bitrate TEXT NOT NULL,
    file_size INTEGER,
    duration INTEGER,
    title TEXT,
    artist TEXT,
    album TEXT,
    created_at TEXT NOT NULL,
    last_used_at TEXT NOT NULL
);
```

### Таблица пользователей

```sql
CREATE TABLE users (
    telegram_user_id INTEGER PRIMARY KEY,
    username TEXT,
    first_name TEXT,
    role TEXT NOT NULL DEFAULT 'friend',
    created_at TEXT NOT NULL,
    last_seen_at TEXT NOT NULL
);
```

### Таблица событий

```sql
CREATE TABLE events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    telegram_user_id INTEGER,
    navidrome_song_id TEXT,
    event_type TEXT NOT NULL,
    context TEXT,
    created_at TEXT NOT NULL
);
```

Примеры event_type:

```text
search
send
radio
cache_hit
cache_miss
transcode_error
```

## 18. Безопасность

MVP должен быть закрытым.

Минимальные требования:

* доступ только по `ALLOWED_TELEGRAM_USER_IDS`;
* не показывать внутренние URL Navidrome;
* не отдавать прямые ссылки на файлы без необходимости;
* не логировать пароли и токены;
* хранить токены только в `.env`;
* не открывать публичную регистрацию.

## 19. Производительность

Основное потенциально тяжелое действие — транскод.

Ограничения MVP:

* не запускать слишком много ffmpeg-процессов параллельно;
* использовать кэш Telegram `file_id`;
* повторно не транскодировать уже отправленные треки;
* хранить MP3-кэш опционально;
* чистить временные файлы после отправки.

Рекомендуемый лимит:

```text
1–2 параллельных транскода
```

## 20. Логирование

Логировать:

* старт приложения;
* успешное подключение к Navidrome;
* успешное подключение к Discocs;
* поисковые запросы;
* отправку треков;
* cache hit/cache miss;
* ошибки транскода;
* ошибки API;
* denied access.

Не логировать:

* Telegram bot token;
* пароль Navidrome;
* полные приватные download URLs.

## 21. Критерии готовности MVP

MVP считается готовым, если:

1. Бот запускается в Docker.
2. Доступ разрешен только пользователям из allowlist.
3. `/start` и `/help` работают.
4. `/search <query>` возвращает треки из Navidrome.
5. Под треком есть кнопка `🎧 Отправить`.
6. FLAC-трек транскодируется в MP3 и отправляется в Telegram.
7. После первой отправки трека сохраняется Telegram `file_id`.
8. Повторная отправка того же трека происходит без транскода.
9. Под треком есть кнопка `📻 Радио`.
10. Радио получает похожие треки из Discocs.
11. Рекомендованные треки можно отправить тем же механизмом.
12. Ошибки Navidrome, Discocs и ffmpeg обрабатываются понятными сообщениями.

## 23. Итоговая формулировка MVP

Discocs Bot MVP — это закрытый Telegram-бот, который подключается к Navidrome и Discocs, позволяет искать треки, отправлять их в Telegram как MP3-аудио и строить радио по выбранному треку.

Главная ценность первой версии — не полнота функций, а короткий рабочий путь:

```text
/search → выбрать трек → отправить → радио → отправить похожий трек
```

Если этот сценарий работает быстро и надежно, бот уже решает основную задачу: делает личную музыкальную библиотеку доступной внутри Telegram.
