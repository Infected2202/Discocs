# Социальные функции — спека

Статус: **согласовано UX, к нарезке на исполнение** (октябрь 2026).
Заменяет пункт «Страница профиля пользователя» из `plans/todo.md`.

Цель: видеть, что слушают другие пользователи прямо сейчас, и иметь страницу
своего профиля со статистикой, доступную остальным пользователям.

Контекст: мультиюзер готов (`plans/multiuser-spec.md`), `Store.for_user` —
default-deny. Пользователей ~3, все свои: **всё открыто всем
залогиненным**, никаких тумблеров приватности. Единственное исключение —
приватные плейлисты (уже есть) видит только владелец.

## 1. UX

### 1.1 Шелф «Люди» на главной

- Обычный `Shelf` с `MediaCard`; новый тип карточки `user`: круглый аватар
  на месте обложки (как у `artist`), **без кнопки play**.
- Клик по карточке → профиль `/u/:username`.
- Две строки подписи: 1) логин; 2) «Трек — Артист» **только если сейчас
  играет**, рядом мигающая зелёная точка. Не играет (в т.ч. пауза) — только логин.
- Показываются все пользователи discocs (строки `users`), кроме себя. Сортировка:
  играющие сейчас первыми, затем по `last_login_at`/последнему прослушиванию.
- Шелф скрыт, если других пользователей нет.
- Автообновление статусов раз в ~15 с, пока вкладка видима (react-query
  `refetchInterval` + пауза на hidden).

### 1.2 Аватары

- **Только встроенные**, загрузки своего нет. Набор 5–10 картинок даёт Саня.
- При первом обращении пользователю назначается случайный аватар из набора и
  сохраняется (не меняется между загрузками).
- На своём профиле клик по аватару → существующий `dialog` с сеткой встроенных
  аватаров, выбор сохраняется сразу.
- Сервер принимает только ключ из фиксированного whitelist; файлов от
  пользователя не принимает вообще.

### 1.3 Страница профиля `/u/:username`

Прежде всего — страница **своей** информации и статистики; цели «включить с ходу»
нет. Чужой профиль выглядит так же, кроме приватных плейлистов и выбора аватара.
Одна длинная страница с секциями (как страница артиста), без вкладок.
**Переиспользовать существующие компоненты**, новых не городить.

1. **Шапка** — `CollectionHeader`: круглый аватар (на своём кликабелен →
   выбор аватара), логин, мета «в discocs с <users.created_at>» + счётчики
   за всё время (прослушивания, артисты, лайки). Если играет сейчас — строка
   «Сейчас слушает: Трек — Артист» с зелёной точкой. Кнопок действий нет.
2. **Переключатель периода** — существующий `tabs`: 7д / 30д / 90д / 180д /
   год / всё время, по умолчанию 30д. Управляет статистикой и топами.
3. **Последние прослушивания** — `VirtualTrackList`, ~10 строк, относительное
   время («4 мин назад», «вчера», дата для старше недели). Повторы видны (это
   лента прослушиваний, не уникальные треки). «Все» → полная история с
   подгрузкой, сгруппированная по дням.
4. **Статистика за период** — сводка (прослушивания, часы, уникальные артисты);
   столбики по дням; распределение по часам суток; звуковой профиль (топ
   жанров/настроений из `track_predictions`). Графики — **простые столбики на
   div'ах**, без библиотек графиков.
5. **Топ артистов**, **топ релизов** — `Shelf` + `MediaCard`, в подписи число
   прослушиваний.
6. **Топ треков** — `VirtualTrackList` с числом прослушиваний.
7. **Лайки** — шелфы лайкнутых треков/релизов/артистов (как существующие
   полки лайков).
8. **Плейлисты** — шелф; на чужом профиле только public.

Входы: шелф «Люди»; пункт «Мой профиль» в попапе `ProfileButton`.

### 1.4 Мелочь на главной

Полка «История» получает подпись относительного времени на карточках
(`last_played_at` уже есть в запросе `_dashboard_history`).

### 1.5 Вне скоупа (решено)

Shoutbox, открытия месяца, человек на карте коллекции, совместимость вкусов
(«потом»), отправка трека/реакции/совместное прослушивание, загрузка своего
аватара, тонкие настройки приватности.

## 2. Технические решения

### 2.1 Что такое «прослушивание»

То же правило, что скроббл в Navidrome: `should_scrobble_navidrome_play`
(`app/serializers/playback.py`) — `play_threshold_reached`, либо `completed`
без предшествующего порога в том же queue item. Чтобы статистика по периодам
была простой и быстрой SQL-агрегацией, решение материализуется:

- Новая таблица `listens(id, user_id, track_id, listened_at, event_id UNIQUE)`
  + индексы `(user_id, listened_at)`, `(user_id, track_id)`.
- Пишется в момент, когда событие признано скробблом (тот же предикат, одна
  точка решения — не дублировать логику), независимо от того, удался ли
  вызов Navidrome и включён ли он вообще.
- Миграция-бэкфилл из `playback_events` (у них есть `user_id`) тем же
  Python-предикатом, идемпотентно.
- Артисты/релиз для топов — join на момент запроса (`tracks`, track-artists).

### 2.2 Чтение чужого профиля

Не ослабляем default-deny. Отдельный сервис `app/services/profile.py`:
резолвит `username → user_id` (без учёта регистра, как в `users`), строит
`Store.for_user(target_id)` и вызывает **только** явный набор read-методов,
собирая ответ из whitelisted полей. Правила:

- Приватные плейлисты — только если `viewer_id == target_id`.
- Никогда не отдаются: flow-профиль, сессии/очередь, `user_settings` (кроме
  ключа аватара), Navidrome-креды, preference-score/дизлайки.
- Service-принципал без `user_id` → отказ; неизвестный username → 404.
- Двухпользовательские тесты на каждое правило.

### 2.3 Статусы «сейчас слушает» — из Navidrome

Navidrome последний, поддерживает OpenSubsonic `playbackReport`.

**Запись.** Новый лёгкий эндпоинт `POST /api/v1/playback/presence`
`{track_id, state: starting|playing|paused|stopped, position_ms}` → бэкенд
вызывает `reportPlayback(mediaId, mediaType=song, positionMs, state,
ignoreScrobble=true)` кредами текущей сессии (как star/scrobble).
В `playback_events` **не пишется** (не трогает логику предпочтений).
Клиент шлёт: старт трека, пауза, продолжение, перемотка, стоп/конец очереди;
на `pagehide` — `stopped` через `sendBeacon`. Ветка `now_playing`
(`scrobble submission=false` на `track_started`) удаляется; наш
`scrobble(submission=true)` остаётся как есть.
*Проверить вживую:* что `ignoreScrobble=true` не даёт двойного счёта и что
без него Navidrome сам бы засчитал play.

**Чтение.** `GET /api/v1/social/people` → список пользователей discocs кроме
себя: `{username, avatar, now_playing: {track_id|null, title, artists, state} | null}`.
Бэкенд вызывает `getNowPlaying` **сервисным** аккаунтом, кэш ~5 с в процессе;
берёт только `state ∈ {starting, playing}`; сопоставляет username → `users`
(без учёта регистра), `mediaId` → трек через `get_track_by_external_id
("navidrome", …)`. Немаппленный трек — показываем title/artist из ответа
Navidrome, без ссылки. Navidrome недоступен → `now_playing: null` у всех,
шелф не ломается. *Проверить вживую:* что сервисный аккаунт видит сессии всех
пользователей.

### 2.4 Аватары

- Файлы — `ui/src/assets/avatars/<key>.webp` (Vite-ассеты), ключи `a01…a06`
  (6 картинок от Сани, ужаты до 512×512 WebP, уже лежат в репо).
- Бэкенд: whitelist ключей в одном модуле (`app/avatars.py`); тест сверяет, что
  у каждого ключа есть файл в `ui/src/assets/avatars/`.
- Хранение: `user_settings` ключ `avatar` (без миграции схемы). Назначение
  случайного — лениво при первом чтении (people/profile/me) и при апсёрте юзера.
- `PUT /api/v1/me/avatar {key}` — только свой; ключ вне whitelist → 422.
- Добавление аватара = файл + ключ в whitelist.

### 2.5 Часовой пояс

Сервер хранит UTC. Бакеты «по дням» и «по часам» считаются в поясе зрителя:
фронт передаёт IANA-имя (`Intl...timeZone`), бэкенд валидирует через
`zoneinfo`, невалидное → UTC.

## 4. Фазы

Порядок: **Ф1 → (Ф2 ‖ Ф3) → (Ф4 ‖ Ф5)**. Каждая фаза — код + тесты + док
(`docs/social.md`, по мере появления; правки `docs/data-model.md`,
`docs/web-ui.md`). Параллельные фазы — в отдельных worktree, затем мерж и
ревью. **Пуш — по фазам** (решение Сани): фаза закоммичена → push → зелёный
CI → следующая волна.

**Ф1. Фундамент (backend).** Таблица `listens` + запись в точке решения о
скроббле + бэкфилл-миграция; `app/avatars.py` + назначение/смена аватара +
`GET /users`, `PUT /me/avatar`; каркас `app/services/profile.py`
(резолв username, target-scoped store, правила §2.2).
Тесты: запись listen ровно по правилу скроббла (порог, completed без порога,
дубль), идемпотентный бэкфилл, whitelist аватара, чужой аватар не сменить,
изоляция профиля.

**Ф2. Присутствие (Navidrome + плеер).** `NavidromeClient.report_playback`,
`get_now_playing`; `POST /playback/presence`; удаление ветки `now_playing`;
`GET /social/people` с кэшем и маппингом; во фронте — отправка состояний из
плеера (пауза/продолжение/перемотка/стоп, `sendBeacon` на pagehide).
Тесты: маппинг username/mediaId, фильтр по state, недоступный Navidrome,
креды сессии, отсутствие записи в `playback_events`.

**Ф3. API профиля (backend).** Эндпоинты профиля: счётчики за всё время,
сводка/столбики по дням/по часам/звуковой профиль за период с учётом `tz`,
топы артистов/релизов/треков, лента прослушиваний с пагинацией, лайки,
плейлисты (private только себе). Тесты на агрегации по периодам и границам
суток в поясе, на приватность.

**Ф4. UI главной.** `MediaCard` тип `user` (круглый аватар, без play, вторая
строка + мигающая точка); шелф «Люди» с поллингом; относительное время на
полке «История»; «Мой профиль» в `ProfileButton`; i18n. Тесты компонентов.

**Ф5. UI профиля.** Роут `/u/:username`; шапка на `CollectionHeader`; диалог
выбора аватара (свой профиль); переключатель периода на `tabs`; секции §1.3;
столбики на div'ах; полная лента прослушиваний по дням; i18n, мобильная
вёрстка. Тесты страницы (свой/чужой, пустые состояния, смена периода).
