# Полка «Лейблы»

Статус: **реализовано (первая версия).** Открытые вопросы по качеству названий
лейблов (ниже, «Отложено») решаем по итогам ветки анализа лейблов — реализации
они не мешают.

## Как сделано

- **Источник лейбла — Navidrome.** `getAlbumList2` отдаёт OpenSubsonic `recordLabels`
  у альбома (у песен их нет; в снимке music-fill — у 12 479 из 14 725 альбомов, у 474
  несколько лейблов). Синк уже ходил туда за типом релиза — теперь подмешивает в raw
  песни ещё `recordLabels` и `releaseDate` (тоже только у альбома, объектом
  `{year, month, day}`; раньше discocs дату релиза не получал вовсе).
- Схема: `labels` + `release_labels` (many-to-many, порядок как в тегах) — см.
  `docs/data-model.md`. Лейбл = нормализованное название; `[no label]` не лейбл.
- API: `GET /api/v1/labels`, `/labels/{id}`, `/labels/{id}/releases?sort=`,
  `/labels/{id}/image` (своя картинка или заглушка Beatport),
  `PUT /api/v1/labels/metadata` (для `tools/label-sync`, картинка — base64 в JSON).
- Полка `labels` на дашборде, страница `/labels/:id` (`ui/src/pages/LabelPage.tsx`),
  переключатель сортировки «сначала новые / старые» — см. `docs/web-ui.md`.
- `tools/label-sync/` — синхронизация картинок/описаний/ссылок, см. его README.
  Проверено вживую: Trip, Ninja Tune, Suara находятся по штрихкоду и на Beatport, и
  на Discogs; у Ninja Tune — описание из русской Википедии.
- Штрихкод Deezer совпадает с Beatport/Discogs не у всех: у Suara (дистрибуция
  Believe/Ingrooves) — примерно у одного релиза из десяти, большие сборники почти
  никогда. Поэтому скрипт идёт от релизов с меньшим числом файлов и перебирает до 40
  штрихкодов, пока лейбл не подтвердится (совпало название или два голоса).

## Решено

### Полка на дашборде

- Карточка лейбла: картинка + название.
- Порядок — по числу релизов лейбла в библиотеке, по убыванию.
- Порога по числу релизов нет.
- «Смотреть все» — обязательно, как у остальных полок.

### Страница лейбла

- Список (сетка) релизов лейбла.
- Сортировка по **дате релиза** (`release_date`), не по оригинальной дате.
  Если у релиза известен только год — сортировка по году, внутри года по названию.
- Кнопок («играть всё» и т.п.) и фильтров (по типу релиза) нет; есть только выбор
  направления сортировки (из исходной постановки «можно сортировать по дате выпуска»).
- Текстовое описание лейбла и ссылки лейбла — см. «Решено: описание лейбла» ниже.

### Картинки лейблов

- Один раз выкачиваются и хранятся у discocs; хотлинка на внешние CDN нет.
- Источники по приоритету: **Beatport** → **Discogs**. Сгенерированные обложки
  (коллаж из релизов) — не подходят. Ручная загрузка — не сейчас, добавим при
  необходимости.
- Если картинки нет нигде — показываем заглушку Beatport (серый квадрат со значком
  Beatport), сохранённую как статический файл приложения.
- Заглушку Beatport сам Beatport отдаёт вместо логотипа у лейблов без картинки
  (видели: Hyperboloid Records, Kos.Mos.Music) — её узнаём по id файла
  `cda9862c-cf92-4d13-ac65-7e9277181f51` и считаем «картинки нет» (идём в Discogs).
- Beatport отдаёт `image.uri` разного размера (бывает `60x60`) — брать через
  `image.dynamic_uri` с нужным размером (500×500 есть и у таких).

Сравнение на кэше music-fill (38 лейблов Beatport, 3 Discogs): Beatport — квадратные
500×500 чистые логотипы почти у всех; Discogs — разный размер/пропорции, иногда не
чистый логотип.

### Сопоставление — через релиз, не по названию

Поиск лейбла по названию ненадёжен: Discogs по «Trip» отдаёт американский TRIP
(Springboard), а не «Трип» Нины Кравиц. Поэтому:

- Релиз находится по **штрихкоду** (`BARCODE` в тегах deemix; UPC Beatport = UPC Deezer,
  это уже используется в music-fill), лейбл берётся из найденного релиза.
- Для размеченного Picard (`!OLD!`) — у лейбла MusicBrainz часто есть ссылка на
  Discogs-лейбл: тоже точная связь (проверить по месту).

### Синхронизация: скрипт в `tools/`

- Простой скрипт в `tools/` (рядом с music-fill, интеграции Beatport API v4 и Discogs
  уже есть там — переиспользовать). Токены Beatport/Discogs остаются на рабочей машине,
  на сервер discocs не попадают.
- Вход: `tools/library-tags/cache/scan.json` — «лейбл → штрихкоды» из тех же тегов,
  откуда discocs берёт названия лейблов.
- Результат передаётся в discocs **через API**: {название лейбла, источник, внешние id,
  картинка, описание + его источник, ссылки}. discocs сопоставляет со своим лейблом по нормализованному названию —
  скрипту не нужны внутренние id discocs.
- Запускается разово, повторно — по необходимости (новые лейблы).

## Отложено до итогов ветки анализа лейблов

- Масштаб проблем и решения:
  - варианты написания («Ninja Tune» / «Ninja Tune Ltd.») → `label_aliases`
    по аналогии с `artist_aliases`;
  - несколько лейблов на релиз — схема уже many-to-many, но варианты одного
    лейбла в одном релизе («Tresor» + «Tresor Records») сейчас дают два лейбла;
  - дистрибьюторы вместо лейблов (Believe, DistroKid, «Records DK»),
    «Self-released» («[no label]» уже отбрасывается);
  - саблейблы/родительские лейблы.

## Решено: описание лейбла

Что дают источники (на кэше music-fill):

- **Beatport** — поле `bio`. Заполнено у 1 из 38 лейблов, и то однострочник
  («Independent techno label / Barcelona / Est. 2008 / Led by Coyu»).
- **Discogs** — `profile` + `urls` (сайт, Bandcamp, SoundCloud, соцсети). Профиль
  заполнен чаще, но на английском, с разметкой Discogs (`[a=…]`, `[l=…]`,
  `[url=…]…[/url]`, `[b]`) и бывает каталогизаторский (TRIP: «Please ALWAYS denote the
  addresses from the rear cover…»).
- **Wikipedia через Wikidata** — нормальная проза, бывает на русском, связь точная
  (свойство Wikidata «Discogs label ID»). Есть в основном у крупных лейблов.

Решения:

- Источник текста — первый непустой по цепочке: **ru Wikipedia → en Wikipedia →
  Discogs `profile` → Beatport `bio`**. В UI подпись, откуда текст.
- Discogs запрашивается **всегда**, даже если картинку дал Beatport: из него описание,
  ссылки и id для поиска в Wikidata.
- Разметка Discogs → обычный текст; `[a=Артист]` — ссылка на страницу артиста discocs,
  если он есть в библиотеке, иначе просто имя.
- Ссылки лейбла из Discogs `urls` показываются под описанием.
- Длинный текст сворачивается после 3–4 строк («показать полностью»).
- Каталогизаторские профили — оставляем как есть; скрытие/переопределение добавим,
  если начнут мешать.

### Кэширование

- Скрипт кэширует ответы всех внешних API на диске рядом с собой (как music-fill:
  `cache/*.json` с TTL, в git не попадают) — повторный прогон не дёргает Beatport,
  Discogs, Wikidata и Wikipedia заново.
- discocs хранит переданный результат (картинку, текст, источник, ссылки) у себя;
  страница лейбла во внешние сервисы не ходит никогда.
