# music-fill

Локальный инструмент: добирать в библиотеку Navidrome недостающее — по истории прослушиваний
(YouTube Music, Last.fm), по дискографиям артистов и по каталогам лейблов. Качает deemix (Deezer),
а то, чего на Deezer нет, — Soulseek через slskd.

Работает на рабочей машине, не в CI и не в образах discocs (см. [../README.md](../README.md)).

## Запуск

```bash
python review_server.py      # http://127.0.0.1:8765
```

- `/` — разбор: артисты, альбомы-дыры, треки плейлистов, поиск, лейблы (Beatport); решения «в план».
- `/decisions` — план загрузки в deemix, очередь и сверка с диском, вкладка Soulseek, журнал.

Нужны: Python 3.11+ (`requests`, `mutagen`, `websocket-client`), `ffmpeg` в PATH (WAV/ALAC → FLAC),
запущенный deemix-gui (`http://127.0.0.1:6595`), slskd с API-ключом.

## Настройка

`config.json` рядом со скриптами — по образцу [config.example.json](config.example.json). Вход в Beatport —
`python beatport_login.py` (пишет в config.json только токены). Секреты в git не попадают — см. `.gitignore`.

## Модули

| | |
|---|---|
| `review_server.py` | HTTP-сервер и вся логика плана: Deezer, deemix, сверка с диском, лейблы, Soulseek |
| `build.py` | сравнение истории прослушиваний с библиотекой; нормализация названий и артистов |
| `beatport.py`, `discogs.py` | клиенты каталогов; `discogs.title_keys` — общие правила сравнения названий |
| `slsk.py` | поиск в Soulseek каскадом (каталожный номер → артист + релиз → варианты → треки), сверка по длительностям, загрузки slskd |
| `tagger.py` | раскладка скачанного из Soulseek как у deemix: папки, имена, теги, FLAC |
| `journal.py` | журнал событий и бэкапы |
| `kvcache.py` | кэш ответов внешних API в `cache/cache.db` |
| `*_dump.py` | выгрузки Navidrome / YouTube Music / Last.fm |

## Что уже есть

«Есть в библиотеке» в плане берётся из снимка Navidrome (`raw/navidrome/songs.json`). Сервер сам
пересобирает его, когда снимок старше суток, а кнопка обновляет его сразу. Скачанное после снимка
ловит проверка папки загрузок deemix («уже на диске», работает в дозагрузке лейблов). Если папка
недоступна, например сетевой диск не подключён в сессии, где запущен сервер, над планом появляется
предупреждение. Релизы, которые проверить не удалось, тогда не отмечаются.

## Кэш и ночное обновление

Все ответы внешних API лежат в одной SQLite `cache/cache.db`. Раньше это были JSON-файлы на сотни МБ,
которые переписывались целиком на каждую новую запись. При первом запуске старые
`cache/*.json` переносятся в базу (около минуты) и переименовываются в `*.json.imported`. Их
можно удалить, когда всё работает.

План сеть не ждёт: дискографии и каталоги лейблов берутся из кэша в любом возрасте. Чего в кэше
нет (новый артист, новый лейбл), то грузится фоном. В плане такая задача показана как
«загружается…», страница переспрашивает план, пока всё не догрузится. Устаревшее (старше недели)
обновляется по одному в 5:00 (`NIGHTLY_HOUR`): сначала дискографии, потом каталоги лейблов.
Если компьютер в это время спал, обновление начнётся, когда он проснётся. Итог пишется в журнал
событием `nightly_refresh`. Ответы Deezer бессрочные, у Beatport/Discogs свой срок (неделя), у
Soulseek — 3 дня / 6 часов.

## Очередь deemix

Сервер раз в минуту смотрит очередь deemix и пишет в журнал смену статусов. Докачанный релиз сразу
тегируется (`../library-tags/autotag.py`), а треки, которые deemix не нашёл, уходят в Soulseek.
Если релиз «качается», но 15 минут подряд не меняются ни счётчики треков, ни прогресс, он считается
зависшим (`deemix_hung`). Так бывает, когда deemix ходит по кругу запасных ID недоступного трека, и
перезапуск этого не лечит. Такой релиз снимается из очереди, скачанное тегируется, а треки, для
которых нет файла, отправляются в Soulseek.

## Теги файлов из Soulseek

Кроме набора deemix (title, artist, album, albumartist, номер, дата, жанр, ISRC, штрихкод, лейбл, обложка
внутри файла) — свои поля (во FLAC — Vorbis comment, в MP3 — TXXX):
`SOURCE=Soulseek`, `SOURCE_DATE`, `SOURCE_FORMAT` (что было у пира до перегонки), `SOULSEEK_USER`,
`SOULSEEK_FILE`, `MATCH`, `MATCH_DURATION` (ожидали/у файла, с), `BEATPORT_RELEASE_ID`/`BEATPORT_TRACK_ID`
или `DEEZER_ALBUM_ID`/`DEEZER_TRACK_ID`. Picard с «Clear existing tags» их сотрёт.
