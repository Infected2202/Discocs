# agent

Воркер инструментов на ПК: берёт задачи из раздела «Инструменты» админки discocs и выполняет их здесь —
описания лейблов (`tools/describe`), запуск и остановку сервера `tools/music-fill`. Как устроено со стороны
discocs — [docs/tools.md](../../docs/tools.md).

## Что нужно

- Окружение `tools/describe/.venv` (воркер запускает describe в своём процессе) — см.
  [../describe/README.md](../describe/README.md): LM Studio с моделью, SearXNG, FlareSolverr.
- `config.json` — копия `config.example.json` (адреса LM Studio, SearXNG и т.п.). В git не попадает.
- Доступ к discocs — свой ключ воркера (`device.key`, придумывается при первом запуске, в git не попадает).
  Первый запуск — в админке discocs, раздел **Access**, появится запрос «… · Tools worker»: сверить отпечаток
  с журналом (`device … (fingerprint …)`) и нажать Approve. Перезапуск не нужен. `service_token` в `config.json`
  не нужен; если задан и не подходит — воркер его забывает и просит доступ ключом (см. docs/auth.md, «Устройства»).
- Для music-fill — Python с его зависимостями (`music_fill_python`, по умолчанию `python` из PATH).

## Запуск

    ..\describe\.venv\Scripts\pythonw.exe agent.py

`pythonw` — без окна; журнал — `logs/agent.log`. Автозапуск при входе в Windows — задача «discocs tools
agent» в Планировщике заданий («При входе в систему», эта команда, рабочая папка `tools/agent`; упал —
перезапуск до 3 раз через минуту).

## Как ведёт себя

- **Простой.** Один долгий запрос к discocs висит до минуты, пока задачи нет: 0% процессора, ~40 МБ памяти.
  Модель в LM Studio не загружена — видеопамять свободна.
- **Приоритет.** Процесс работает с приоритетом «ниже обычного»: свои задачи на ПК получают процессор первыми.
- **describe.** Перед задачей модель загружается (`lms load`, контекст `model_context`, `jobs` слотов), после —
  выгружается. Лейблы берутся у discocs порциями, по `jobs` одновременно, итог по каждому отправляется сразу:
  текст агента сразу становится описанием лейбла.
- **Игра.** Видеопамять выше `vram_limit_mb` — новые лейблы не берутся, разобранные доделываются, модель
  выгружается, задача на паузе («GPU is busy» в админке). Когда память освобождается настолько, что модель
  (`model_vram_mb`) влезает, — модель загружается обратно, задача продолжается.
- **Пауза и отмена** из админки работают так же: разобранные доделываются, модель выгружается.
- **Сбой.** Пропала связь с discocs — воркер ждёт и продолжает ту же задачу. Задача упала по другой причине
  (например, LM Studio не загрузил модель) — она помечается в админке как упавшая с текстом ошибки.
- **music-fill.** `start` поднимает `review_server.py` без окна (журнал — `music-fill/logs/agent-server.log`),
  `stop` останавливает запущенный воркером сервер. Сервер, поднятый руками, виден по порту, но остановить его
  воркер не может.
