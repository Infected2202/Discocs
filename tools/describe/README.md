# describe

Описания лейблов на русском: локальная модель ищет в вебе, собирает факты с цитатами и пишет по ним текст.
Замена дорогим субагентам Claude — всё крутится на рабочей машине (RTX 4090, 24 ГБ).

## Что нужно

- **LM Studio** с моделью `google/gemma-4-26b-a4b-qat` (OpenAI-совместимый API на `127.0.0.1:1234`):

      lms load google/gemma-4-26b-a4b-qat -c 81920 --parallel 3 --gpu max -y

  Занимает ~21.6 ГБ видеопамяти вместе с рабочим столом. Игра или другая тяжёлая программа на GPU — и модель
  вылетает из памяти; прогон не запускать.
- **SearXNG** в Docker на `127.0.0.1:8888` — поиск. В `settings.yml` обязательно `search.formats: [html, json]`
  (иначе JSON API отвечает 403), `server.limiter: false`; brave и duckduckgo выключены — банят быстро. Движки
  задаются в `config.json` (`searxng_engines`): yandex, yahoo, google cse.
- **FlareSolverr** (homelab, `192.168.1.41:8191`) — запасной путь для страниц за JS-проверкой (Bandcamp Daily и т.п.).
- Python 3.11+ с `requests` и `trafilatura` в `.venv`:

      python -m venv .venv && .venv/Scripts/pip install requests trafilatura

`config.json` — копия `config.example.json` со своими адресами; в git не попадает.

## Запуск

    .venv/Scripts/python -u run.py labels.json --model=google/gemma-4-26b-a4b-qat --jobs=3 [id ...]

- `labels.json` — список `{id, name, external_ids, artists, releases}`; выгрузка из базы discocs —
  `export_labels.py` (как запускать — в самом скрипте).
- Результат — `out/<id>.json`: текст, все факты с цитатами и адресами, запросы, прочитанные страницы, время по
  шагам, заметки проверки.
- `--rewrite` — только текст заново по фактам из `out/<id>.json`, без поиска (1–3 минуты на лейбл): для правок
  отбора и промптов текста.
- `--jobs` не больше `--parallel` модели, иначе запросы встанут в очередь.

Время: 1.5–11 минут на лейбл при трёх параллельных, крупные лейблы (Defected, Dirtybird) — дольше всех.
Две трети времени — разбор страниц на факты.

## Как устроено

Модель ничего не делает сама: не пишет адресов, не ходит по ссылкам — только выбирает номера из выдачи и
отвечает по JSON-схеме. Все действия — в коде. Поэтому инъекция в тексте страницы может испортить факт, но не
заставит открыть что-то во внутренней сети: чтение ходит только на публичные адреса (`web._check_public`,
и после редиректов FlareSolverr тоже).

1. **Каталог.** Артисты лейбла по его ID с Beatport (`__NEXT_DATA__` страницы лейбла) и Discogs API — плюс
   артисты и релизы из библиотеки. По ним код решает, «тот ли это лейбл» на найденной странице
   (`Subject.identified_by`): одно сильное совпадение (артист, многословное название релиза) или два слабых.
   Без этого агент описывал одноимённый лондонский хип-хоп лейбл вместо российского drum and bass.
2. **Известные источники.** Профиль Discogs, Википедия через Wikidata.
3. **Поиск.** Модель пишет запросы → SearXNG → модель выбирает до 12 страниц (статьи и интервью первыми), во
   втором раунде — ещё до 6 под пробелы (нет основателей, года, звучания). Соцсети, стриминги, магазины и
   агрегаторы (`web.SKIP_DOMAINS`) отсекаются ещё в выдаче: фактов там нет, только «X выпустил Y».
4. **Факты.** Страница режется на куски по 2500 символов, из каждого модель выписывает факты с дословной цитатой
   (маленькая модель на длинном тексте пропускает большую часть). Факт без найденной в тексте цитаты
   выбрасывается.
5. **Отбор.** Модель оценивает каждый факт — тема и интересность 0–3, партиями по 25; набирает код: склеивает
   дубли (`_similar`), берёт лучшие с потолком на тему (`TOPIC_LIMITS`), максимум 16. Выбрать 16 из сотни
   сама модель не может: без размышлений берёт первые по порядку, с размышлениями думает бесконечно.
6. **Сомнительное.** Код сравнивает факты одного типа (год, место, основатели) и ищет оговорки; расхождения
   модель проверяет отдельным поиском с цитатой. Модель-«судья» без поиска была параноидальной и выкидывала верное.
7. **Текст** без размышлений (с ними тот же результат в 40 раз дольше) по фактам и их цитатам — краски живут в
   цитате, не в пересказе. Длина задаётся предложениями: с лимитом в символах модель начинала считать буквы.
8. **Проверка.** Модель сверяет текст с фактами и цитатами (неподтверждённое, «кто есть кто») и с правилами
   (перечни без истории, каталожные номера, непереведённый английский, ссылки на источники); номера и английские
   фразы дополнительно ловит код (`_style_flags`). Есть замечания — одна правка.
9. **Корректура** — орфография; правка, задевшая разметку `[a=…]`, числа, латиницу или длину, отбрасывается.

## Известное

- Выдача поиска плавает: редкая статья (Afisha, история с Siriusmo у Monkeytown) находится не в каждом прогоне.
- О мелком лейбле артиста в сети бывает только об артисте — текст выходит об артисте (Receptor).
- Отправка в discocs и описания артистов — ещё не сделаны.
